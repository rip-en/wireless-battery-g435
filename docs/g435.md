# Logitech G435 LIGHTSPEED receivers

The G435 does **not** speak HID++. Battery is only available through the dongle’s vendor bridge, and each read can briefly interrupt audio. The driver therefore caches the last reading for 45 minutes (5 minutes after a failed read, while the headset is off) and also refreshes when you click *Refresh now*. A failed read keeps the previous percent visible as asleep.

| Receiver | USB ID | Bridge | Collection |
|---|---|---|---|
| Original Realtek | `046D:0ACB` | Realtek PA / bootloader | usage page `FFC0`, feature report 6 |
| Newer Holtek | `046D:0ADF` | Holtek CRC-16/XMODEM | usage page `FF00`, 64/65-byte reports |

## Realtek (`0ACB`)

1. Enter bootloader (`06 01 03`) — mutes USB audio while open  
2. Remote mode (`PA 0E E1 01`) so OTA commands reach the headset  
3. OTA get battery (`PA 06 00 31`) → reply contains `06 80 00 <mV LE16>`  
4. Local mode (`PA 0E E1 00`)  
5. Exit bootloader (`06 08 03`) — always runs  

Without remote mode the dongle answers with its own junk value (~102 mV). Only 3000–4500 mV is accepted.

Sources: [fr0styJS/g435-lightspeed-battery](https://github.com/fr0styJS/g435-lightspeed-battery), WirelessBattery PRs #72 / #93, endes’ DEV write-up.

## Holtek (`0ADF`)

1. Disable bridge power saving (`hid_cmd 0x85`)  
2. Confirm the headset is linked (`LQ E6`, bit `0x08`)  
3. Switch to remote mode if needed (`LQ E1 01`), read battery (`OTA 0x31`), restore local mode

The whole attempt, including the restore, stops after 4 seconds so a silent headset cannot stall polling.  

Sources: [DsGrilo/G435-Battery-app](https://github.com/DsGrilo/G435-Battery-app).

## Accuracy

Millivolts are exact. Percentage is a generic 3.7 V Li-ion estimate — Logitech publishes no G435 discharge table.

## Performance notes

- The Realtek path **must** leave bootloader mode after every read. This build uses an RAII exit so a failed query cannot leave the dongle wedged (which freezes USB audio and can stall the PC).
- Reads are rate-limited to once per **45 minutes** after a success, and once per **5 minutes** after a failed read. A USB re-enumerate mid-read will not start another query.
- The first USB read is deferred ~20 seconds after launch; the last good reading is restored from the registry so the tray can show a value immediately. `WirelessBattery.exe --list` bypasses that defer and reads once (audio may mute for about a second on the Realtek receiver). `WirelessBattery.exe --dump` only enumerates HID collections and does not open the bridge.
- The process runs at below-normal priority and polls other HID devices every 90 seconds.
- Default display is **tray icons**, not the taskbar child widget. Right-click → *Show on the taskbar* if you want the widget (UI Automation was removed so it stays lighter).
